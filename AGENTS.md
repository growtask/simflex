# Simflex CMS — правила работы для агентов

Этот файл лежит в ядре и описывает общие правила для всех проектов на Simflex CMS.
Локальные особенности конкретного проекта (пути, окружение, текущие задачи) — в `.agents/local.md` проекта.

## Из чего состоит CMS

- **Ядро** (`growtask/simflex`) — composer-пакет с кодом CMS. Подключается в проект через composer;
  при разработке ядра — как path-репозиторий с симлинком (`vendor/growtask/simflex` → локальный клон ядра).
- **Шаблон** (`simflex-template`) — заготовка сайта. Клонируется, и на нём стартует разработка очередного сайта.
  Шаблон может переопределять и расширять то, что задано в ядре.
- **Документация** (`simflex-docs`) — отдельный репозиторий (mkdocs).

Пути до локальных клонов ядра, шаблона и документации должны быть указаны в `.agents/local.md` проекта.
Если их там нет — спроси у пользователя и допиши.

## Общие правила

- Разрабатывается CMS 4.0; обратная совместимость с CMS 3.6 не требуется.
- Если изменение затрагивает ядро — вноси его в ядро (локальный клон), а не в `vendor` как копию и не в шаблон обходным путём.
  То, что не используется в ядре, задаётся в шаблоне.
- При изменениях в шаблоне или ядре поддерживай документацию в актуальном состоянии.
- Комментарии в коде (PHPDoc, `//`, `#`, HTML-комментарии в шаблонах) пиши на русском.
- Метод-геттер (возвращает значение, ничего не меняя) называется с `get`: `getUpdateData()`, `getTableName()`;
  булев геттер — с `is`/`has`/`can`: `isActive()`, `hasRows()`, `canEdit()`.
- Для функциональных изменений пиши acceptance-тесты. Запускай их через `sudo docker compose`.
- Промежуточный PHP-код запускай только в Docker через `sudo docker compose`: локальная версия PHP может отличаться от версии сайта.
  Временные PHP-файлы можно создавать в корне проекта и удалять после проверки.
- Если нужны изменения в БД, можно менять существующие миграции и выполнять полный прогон миграций заново.
- Автоматически не коммитить, всегда спрашивать.
