# Нейминг и стиль кода

Правила для всех, кто пишет код ядра, шаблона и расширений Simflex CMS (в том числе для агентов). Подробное
описание с примерами — `docs/dev/conventions.md` документации. Файл дополняется по мере появления новых правил.

## Общее

- Стиль — PSR-1, PSR-12, PSR-4 и `.php-cs-fixer.php` шаблона (он проверяет и ядро): `make cs-fix`. Статический
  анализ — `make phpstan` в Docker, ошибок быть не должно.
- Имя говорит о содержимом: по имени переменной, метода, константы, класса должно быть понятно, что это такое, без
  чтения кода. Не использовать общие слова (`$data`, `$item`, `$tmp`, `$res`), если есть точное; не называть
  сущность тем, чем она не является.
- Одна сущность — одно имя во всём коде, документации и тестах. Если сущность переименована, переименовываются все
  её использования: код, шаблоны `.tpl`, тесты (в том числе строки для `ReflectionProperty`), документация.
- Составное понятие называется так, как оно называется в предметной области: набор колонок `time_create` и
  `time_update` — default timestamps (`getDefaultTimestampsColumns()`), а не «auto time».
- Комментарии (PHPDoc, `//`, `#`, HTML-комментарии в шаблонах) — на русском. Теги PHPDoc, типы, имена и примеры кода
  внутри комментария остаются как есть. Комментарий объясняет, зачем, а не пересказывает код.

## Регистр и формат

| Что | Формат | Пример |
|---|---|---|
| Классы, интерфейсы, трейты, enum | `StudlyCaps` | `UserRole`, `FieldForeignKey` |
| Методы | `camelCase` | `getLabel()`, `saveGroup()` |
| Свойства классов (в том числе статические) | `camelCase` | `$isText`, `$roleId` |
| Параметры и локальные переменные | `camelCase` | `$pageSize`, `$isFilter` |
| Константы классов | `UPPER_CASE` через подчёркивание | `REMEMBER_ME_INTERVAL` |
| Namespace | `StudlyCaps`, ядро — `Simflex\Core\`, расширения — `Simflex\<Имя>\` | `Simflex\Core\Admin\Fields` |
| Файл с классом | имя файла = имя класса, путь повторяет namespace | `UserRole.php` |

- В `snake_case` остаются только имена вне PHP-кода: таблицы и колонки БД (`user_role`, `role_id`), ключи массивов
  из БД или запроса (`$row['role_id']`, `$request->post('login')`).
- Привилегии объявляются константами класса (`\Simflex\Core\System\Privilege::ADMIN`,
  `\App\Core\Privilege::MANAGER`, `\Simflex\Catalog\Privilege::CATALOG`) и используются только через них, а не
  строками.

## Переменные и параметры

- Переменная, в которой массив или коллекция, называется во множественном числе: `$columns`, `$rows`, `$ids`.
  Одно значение — в единственном: `$column`, `$row`, `$id`.
- Переменная называется по тому, что в ней лежит, а не по тому, из чего она получена. Колонки БД — `$timeColumns`,
  а не `$time` (это не единицы времени); идентификаторы — `$ids`, а не `$list`.
- Булевы переменные и параметры — с `is`/`has`/`can`/`should`: `$isActive`, `$hasChildren`.
- Не использовать однобуквенные имена вне коротких циклов и замыканий (`$i` для индекса, `$e` для исключения,
  `fn($row) => …`).
- Не сокращать слова без необходимости: `$category`, а не `$cat`; общепринятые сокращения (`$id`, `$url`, `$html`,
  `$sql`) допустимы.

## Методы

- Геттер (возвращает значение, ничего не меняя) начинается с `get`: `getUpdateData()`, `getTableName()`. Булев
  геттер — с `is`/`has`/`can`: `isActive()`, `hasRows()`, `canEdit()`.
- Метод, который меняет состояние или делает действие, называется глаголом: `save()`, `reload()`, `addColumn()`.
- Метод, возвращающий HTML, возвращает строку (`return $html`), а не печатает через `echo`; `echo` допустим только в
  системном слое (`Response`, `Page::execute()`, шаблоны `.tpl`) и в консольных командах.
- У методов с похожим смыслом одинаковые имена и порядок параметров во всех классах.

## Константы

- Константа, задающая имя колонки БД, начинается с `COLUMN_`: `COLUMN_TIME_CREATE`, `COLUMN_TIME_UPDATE`. Константа,
  которую наследник может переопределить в `null` (колонки нет), объявляется с типом `?string`.
- Значения, которые встречаются больше одного раза или имеют смысл, выносятся в константы класса, а не пишутся
  «магическими» строками и числами.

## Каталоги и классы

- Каталог с однотипными классами — во множественном числе: `Models`, `Components`, `Handlers`, `Fields`,
  `Transports`. Каталог с разнородными классами одной подсистемы — в единственном: `Price`, `Mail`, `Http`.
- Один класс (интерфейс, трейт, enum) — один файл.
- Статика сайта — `public/assets/<тема>/`, ровно один уровень вложенности.

## Работа с запросом, базой и путями

- Параметры запроса читаются из `Request` (`->get()`, `->post()`, `->request()`, `->file()`, `->server()`,
  `->getPath()`), а не из `$_REQUEST`, `$_GET`, `$_POST`, `$_FILES`, `$_SERVER`; сессия — `System\Session`.
- Запросы к базе — через модели и `AQ`; таблицы без модели — `DB::insert()`, `DB::delete()`. Прямой SQL
  (`DB::query()`, `DB::assoc()`) пишется только в слое ORM (`DB`, `AQ`, `Where`, `ModelBase`, `Schema`) и в DDL
  миграций.
- Новая запись модели — `save()` у экземпляра или статический `Model::insert([...])`; публичного `insert()` у
  экземпляра нет.
- Пути страниц и ссылки — без конечного «/»: `/catalog`, `/user/orders`; корень — `/`.
- Глобальных констант `SF_*` нет: пути на диске — `Container::getPaths()`, где выполняется код —
  `Container::getLocation()`.

## Миграции

- Каждая новая таблица получает default timestamps (`time_create`, `time_update`) автоматически; таблица без них —
  `$c->noTimestamps()`, с одной колонкой — `$c->timestampsOnlyTimeCreate()` / `$c->timestampsOnlyTimeUpdate()`.
  В модели такой таблицы константы `COLUMN_TIME_CREATE` / `COLUMN_TIME_UPDATE` переопределяются в `null`.
- Каждая миграция обратима: `down()` убирает то, что создал `up()`.

## Тесты и документация

- Для функционального изменения — acceptance-тест; тест убирает за собой то, что создал, в `finally`.
- Тесты, промежуточный PHP-код и `./sf` запускаются только в Docker шаблона (`docker compose exec app …`).
- Документация меняется вместе с кодом; заметное изменение — в `CHANGELOG.md` (Keep a Changelog), несовместимое —
  в «Несовместимые изменения».
